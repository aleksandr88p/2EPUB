# 2EPUB

[English](README.md) | [Русский](README.ru.md)

**Локальный Python-конвертер, объединяющий английский оригинал книги и русский литературный перевод в один EPUB с параллельным текстом.**

Каждый английский абзац отображается **жирным**, прямо под ним — русский перевод обычным шрифтом. Цель — комфортное чтение книг на английском с возможностью сразу видеть перевод.

> Статус: **MVP v0.1** — рабочая, но экспериментальная CLI-версия.
> В будущем конвертер станет одной из функций более крупного приложения
> для чтения и изучения языков (см. [Дальнейшее развитие](#дальнейшее-развитие)).

## Текущий статус

Реализовано и проверено end-to-end на реальной книге:

- Чтение исходных FB2 (главы, типизированные абзацы, предложения).
- Сопоставление глав через динамическое программирование.
- Сегментация текста на предложения (EN и RU).
- Мультиязычные эмбеддинги **Qwen3-Embedding-0.6B** (Apple Silicon, MPS).
- Дисковый кеш эмбеддингов — повторные запуски без инференса модели.
- DP-сопоставление предложений с операциями `1:1`, `1:2`, `2:1`,
  `skip_en`, `skip_ru`.
- Восстановление двуязычных абзацев (структура EN-абзацев первична).
- Генерация EPUB: обложка, навигация, стилизация блоков.
- Английские главы без русского соответствия сохраняются (EN-only).
- Автоматические проверки после записи: структура, порядок, полнота текста.
- Два режима: **preview** (первые 2 пары глав) и **полная книга** (`--all`).

## Быстрый старт (macOS)

Требуется Python — разработка и проверка велись на **Python 3.14**
(Apple Silicon); другие версии не тестировались.

```bash
git clone git@github.com:aleksandr88p/2EPUB.git
cd 2EPUB
```

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Модель Qwen3-Embedding-0.6B (~1 ГБ) **скачивается автоматически**
с Hugging Face в `cache/models/` при первом запуске — отдельная
установка не нужна, но для первой генерации требуется интернет.

Проверка готовности (опционально, ~1 с, модель не требуется):

```bash
venv/bin/python -m pytest
```

Предварительная проверка пары книг (опционально, показывает
структурные проблемы исходников):

```bash
venv/bin/python -m bookparse check "books/<английская>.fb2" "books/<русская>.fb2"
```

Генерация preview (первые две сопоставленные пары глав):

```bash
venv/bin/python experiments/build_preview_epub.py
```

Генерация полной книги:

```bash
venv/bin/python experiments/build_preview_epub.py --all
```

Результат появляется в `output/`:

| Режим   | Флаг    | Файл результата             |
|---------|---------|-----------------------------|
| preview | —       | `output/2epub_preview.epub` |
| полная  | `--all` | `output/2epub_full.epub`    |

> Первый запуск долгий: модель считает эмбеддинги для каждого
> предложения книги. Результаты кешируются в `cache/embeddings/`,
> поэтому повторная генерация той же пары книг существенно быстрее.

## Работа с книгами

- Входные книги кладутся в `books/` (папка в `.gitignore` — книги в
  Git не попадают).
- Поддерживаемый формат для сборщика: **FB2** (CLI `bookparse`
  дополнительно умеет читать EPUB для разбора и проверки).
- **Важно:** скрипт-сборщик *не* определяет язык автоматически и *не*
  принимает пути к книгам через CLI. Английский и русский файлы
  заданы константами в начале `experiments/build_preview_epub.py`:

  ```python
  EN_PATH = PROJECT_ROOT / "books" / "blade itslef.fb2"
  RU_PATH = PROJECT_ROOT / "books" / "1 Krov i zhelezo.fb2"
  ```

  Чтобы сконвертировать другую пару книг, положите оба `.fb2` в
  `books/` и поменяйте `EN_PATH` / `RU_PATH`. Файл из `EN_PATH`
  считается английским оригиналом и задаёт структуру; `RU_PATH` —
  перевод.

- Имена выходных файлов — тоже константы (`PREVIEW_PATH`,
  `FULL_PATH`). Флага `--output` пока **нет**.
- Поддерживаемые флаги CLI: `--all` и `-h/--help`. Больше ничего.

## Команды

```bash
# preview EPUB (первые 2 пары глав)
venv/bin/python experiments/build_preview_epub.py

# полная книга (все пары + EN-only главы)
venv/bin/python experiments/build_preview_epub.py --all

# справка сборщика
venv/bin/python experiments/build_preview_epub.py --help

# весь набор тестов
venv/bin/python -m pytest

# разбор структуры одной книги -> cache/<имя>.json
venv/bin/python -m bookparse parse "books/book.fb2"

# предварительный отчёт по паре книг
venv/bin/python -m bookparse check "books/en.fb2" "books/ru.fb2"

# результат сопоставления глав -> cache/align_<en>--<ru>.json
venv/bin/python -m bookparse align-chapters "books/en.fb2" "books/ru.fb2"
```

## Структура проекта

```
2EPUB/
├── bookparse/                  # библиотека: разбор → сопоставление → проверки
│   ├── models.py               # Book / Chapter / Paragraph / Sentence
│   ├── fb2_parser.py           # извлечение структуры FB2 (BeautifulSoup)
│   ├── epub_parser.py          # извлечение структуры EPUB (EbookLib)
│   ├── segment.py              # разбиение на предложения, подсчёт слов
│   ├── chapter_alignment.py    # DP-сопоставление глав + отчёт качества
│   ├── sentence_alignment.py   # DP-сопоставление предложений (AlignOp)
│   ├── paragraph_reconstruction.py  # EN-абзацы + прикреплённый RU-текст
│   ├── embedding_cache.py      # кеш эмбеддингов (.npy на текст)
│   ├── checks.py               # предварительные структурные проверки
│   └── cli.py                  # `python -m bookparse ...`
├── experiments/                # исполняемые скрипты и диагностика
│   ├── build_preview_epub.py   # ★ генератор EPUB (preview + --all)
│   ├── paragraph_preview.py    # предпросмотр двуязычных абзацев -> txt
│   ├── sentence_alignment_diagnostic.py
│   ├── sentence_match_diagnostic.py
│   └── test_embeddings.py
├── tests/                      # набор pytest-тестов
├── books/                      # входные FB2              (в .gitignore)
├── cache/
│   ├── models/                 # веса HF-модели           (в .gitignore)
│   ├── embeddings/             # вектора по текстам .npy  (в .gitignore)
│   └── *.json                  # разобранные книги, результаты выравнивания
├── output/                     # сгенерированные EPUB     (в .gitignore)
├── docs/ARCHITECTURE.md        # техническая документация
├── requirements.txt
└── pytest.ini
```

- `books/` — *ваши* входные файлы.
- `bookparse/` — переиспользуемая библиотека: всё, кроме финальной
  сборки EPUB. На входе и выходе — чистые структуры данных.
- `experiments/` — исполняемые скрипты, связывающие библиотеку воедино,
  включая сам генератор EPUB.
- `cache/` — всё дорогое: веса модели и вектора предложений, чтобы
  повторные запуски не считали инференс заново.
- `output/` — готовые артефакты (EPUB) и диагностические отчёты.
- `tests/` — модульные тесты парсинга, сопоставления, восстановления
  абзацев, кеша и сборщика EPUB.

## Как работает алгоритм

```
EN.fb2 ──┐                          ┌── эмбеддинги (Qwen, кеш)
         ├─► разбор ─► главы ─► предложения ─► DP-сопоставление
RU.fb2 ──┘        └─► DP-сопоставление глав ──┘   предложений
                                                       │
                                                       ▼
EPUB ◄─ ebooklib ◄─ двуязычные абзацы ◄─ восстановление абзацев
```

1. **Разбор.** Оба FB2 превращаются в объекты `Book`: главы →
   типизированные абзацы → предложения.
2. **Сопоставление глав.** DP-проход (в стиле Нидлмана–Вунша)
   сопоставляет главы с заголовками основного тела по объёму текста,
   позиции в книге и уровню вложенности. Непарные и служебные главы
   откладываются отдельно и не теряются.
3. **Сопоставление предложений.** Для каждой пары глав эмбеддинги
   предложений (Qwen3-Embedding-0.6B, нормированные) дают матрицу
   сходства; второй DP-проход строит монотонные операции: пары `1:1`,
   слияния `1:2`/`2:1` (оцениваются по *объединённому* тексту группы)
   и явные `skip_en`/`skip_ru`. Эмбеддинги кешируются на диске.
4. **Восстановление абзацев.** Русские предложения распределяются по
   скелету английских абзацев. Английская книга задаёт структуру и
   порядок — текст не теряется и не дублируется (гарантируется
   контрактом функции).
5. **Сборка EPUB.** Английский абзац **жирным**, под ним русский
   перевод обычным шрифтом; заголовки, эпиграфы и обложка сохраняются;
   главы без пары идут как EN-only разделы.
6. **Проверка.** Готовый EPUB перечитывается и проверяется: точный
   набор глав, порядок по spine, валидный XHTML, полнота и порядок
   EN + RU текста в каждой главе, разрешимость ссылок на изображения.

Зачем эмбеддинги и DP: сходство эмбеддингов даёт попарные оценки, но
выбор лучшего *глобального* монотонного отображения (со слияниями и
пропусками) — именно та задача, которую динамическое программирование
решает быстро и детерминированно.

## Известные ограничения (MVP v0.1)

Версия рабочая, но экспериментальная — идеальное сопоставление
не гарантируется:

- Сопоставление неидеально: русское предложение может оказаться под
  *соседним* английским абзацем. Сложнее всего короткие реплики,
  отдельные строки, письма и эпиграфы.
- Операции `skip_en` / `skip_ru` требуют внимательной интерпретации;
  небольшое число EN-абзацев обоснованно остаётся без перевода.
- Английские главы без русского соответствия включаются **без**
  перевода (front-matter, `Acknowledgments`).
- Русские главы без английской пары (notes, front-matter) в EPUB
  **не включаются** — они перечисляются в отчёте сборки.
- Форматирование FB2 сохраняется частично: курсив (`<emphasis>`)
  схлопывается в простой текст, строки русских стихов объединяются
  в один абзац по структуре английского абзаца.
- Полнота текста проверяется **относительно результата парсинга**, а
  не исходного FB2 — потеря на этапе парсинга не будет замечена.
- Первая книга прошла *частичное* семантическое ревью; полный
  независимый аудит ещё не завершён.
- Пути к книгам и имена выходных файлов жёстко заданы в
  `experiments/build_preview_epub.py` (см.
  [Работа с книгами](#работа-с-книгами)).

## Дальнейшее развитие

### Улучшение конвертера

- Повышение качества сопоставления; исправление смещений между абзацами.
- Улучшение сохранения форматирования (курсив, строки стихов).
- Произвольные входные файлы и имена выходных файлов через CLI
  (`--en`, `--ru`, `--output`).
- Более подробные QA-отчёты по каждой книге.
- Тестирование на разных книгах и переводах.

### Будущее большое приложение (планы, не реализованные возможности)

- Собственная веб-читалка.
- Backend для загрузки и хранения книг.
- Чтение английского текста с параллельным переводом;
  показ/скрытие перевода.
- Интеграция LLM для перевода.
- Адаптация сложности текста под уровень пользователя
  (например, B2 → B1).
- В перспективе — коммерческий сервис.
